<task type="auto">
  <name>Task 2: Create mobile-first responsive CSS</name>
  <files>css/style.css</files>
  <action>
Create css/style.css with:

1. Reset/base styles:
   - Box-sizing border-box on all elements
   - Zero margin/padding reset
   - html font-size 100% (respects user preferences)
   - body: system-ui font stack, line-height 1.5, min-height 100vh AND 100dvh (for mobile browser chrome), romantic background color (soft pink gradient or solid #fff5f8)

2. Utility classes:
   - .hidden { display: none; }

3. Screen layout:
   - .screen: min-height 100vh/100dvh, flexbox centered (both axes), padding 1rem

4. Start button styles:
   - .start-btn: min-width 200px, min-height 48px (touch target), padding 1rem 2rem
   - Romantic styling: pink/red background (#ff69b4 or similar), white text, rounded corners (8px+), no border
   - Touch optimization: touch-action: manipulation, -webkit-tap-highlight-color: transparent
   - Hover/focus states: darker pink, outline for accessibility
   - Active state: subtle scale(0.98) transform

5. Responsive images rule (for Phase 2+):
   - img: max-width 100%, height auto, display block

6. Media queries:
   - Tablet (600px+): increase padding if needed
   - Desktop (1024px+): max-width container if needed

Use CSS custom properties for colors if it helps maintainability.
  </action>
  <verify>Styles apply correctly. Button is centered, has proper hover states, and tap target is at least 48x48px.</verify>
  <done>css/style.css exists with mobile-first responsive styles, touch-optimized button, and proper color scheme.</done>

<task type="auto">
  <name>Task 3: Create JavaScript click-to-start handler</name>
  <files>js/main.js</files>
  <action>
Create js/main.js as an ES module with:

1. State object:
   - { started: false }

2. init() function that:
   - Gets references to #start-screen, #start-button, #main-content via getElementById
   - Adds click event listener to start button that:
     - Guards against double-clicks (if state.started, return)
     - Sets state.started = true
     - Adds .hidden class to start-screen
     - Removes .hidden class from main-content
     - Dispatches custom event 'app:started' on document (for Phase 3 audio)
     - Logs "App started - user gesture captured" for debugging

3. DOM ready handling:
   - If document.readyState === 'loading', wait for DOMContentLoaded
   - Otherwise call init() immediately

4. Export state for potential use by other modules

Use 'click' event (NOT touchend, mouseenter, etc.) - this is critical for browser autoplay policy compliance.
  </action>
  <verify>Click the start button. Console shows "App started" message. Start screen disappears, main content appears.</verify>
  <done>js/main.js exists with click handler that transitions screens and dispatches app:started event.</done>
</task>
